## Intent and simpler alternative

The change adds the minimum catalog foundation: a global Unit of Measure and Organization-owned
Item, with invariants enforced by PostgreSQL. Storing UOM as an Item string would remove one table
but would lose global uniqueness, protected references and reusable identity. Two models are the
smallest design that satisfies Issue #5. No type table, conversion model or shared abstraction is
needed.

## End-to-end trace

1. `config/settings.py` registers Facilities before Catalog, so Organization is available when the
   catalog models load.
2. `catalog.UnitOfMeasure` writes a non-null Unicode name and a globally unique, database-checked
   code.
3. `catalog.Item` writes Organization and base UOM foreign keys using `PROTECT`, plus a code, Unicode
   name and one of `RAW`, `WIP` or `FINISHED`.
4. PostgreSQL checks the Item code, Item type and scoped `(organization, code)` uniqueness.
5. `catalog.0001_initial` depends on `facilities.0001_initial`, creates UOM before Item and matches
   the model state.
6. Tests exercise valid Unicode and empty names, invalid and boundary codes, invalid types, NULLs,
   invalid FKs, independent deletion graphs and concurrent duplicate writes.
7. The 51 unchanged facilities tests pass alongside all 45 catalog tests.
